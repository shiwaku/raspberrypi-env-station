みちびき災危通報の整理

MAX-M10S で受けたみちびきの災危通報を、コワーキングのモニターに出すにあたって調べたこと。現行の仕様書（IS-QZSS-DCR-017・IS-QZSS-DCX-004）とアプリケーションノート第 3.0 版をもとにした。

推測 資料に書かれておらず、資料から判断したこと未確認 資料が見つからなかったこと

4 つの問いへの答え

どんな情報が配信されているか

気象庁の防災気象情報（MT43）12 種類と、J アラート・L アラート（MT44）。気象は特別警報など 4 つの情報だけで、普通の警報・注意報は来ない。

詳しく
配信頻度

MT43・MT44 とも 4 秒に 1 通。同じ通報を 5 分〜24 時間繰り返す。年間件数の統計は見つからない。訓練は月 4 回。

詳しく
ネット配信との違い

衛星は回線なしで届くが、コード化した要約で種類も限られる。気象庁 XML は全文だが、緊急地震速報と J アラートは入っていないとみられる。

詳しく
法的な位置づけ

内閣府の無保証の補完サービスで、公式の警報の伝達手段ではない。そのまま表示するなら許可は不要とみられるが、独自の予想震度などは出さない。

詳しく

災危通報とは

みちびき（準天頂衛星システム）が L1S という信号で送っている防災情報。内閣府のサービスで、誰でも無償で受けられる。L1S は本来、測位の補正情報（サブメータ級測位補強サービス、SLAS）を送る信号で、災危通報はその一部の時間を借りて送られる。

名前メッセージタイプ中身開始
災危通報（DC Report）MT43気象庁の防災気象情報を独自の形式に変換したもの2018
災危通報（拡張）（DCX）MT44J アラート・L アラート・自治体からの直接配信。国際的な共通形式（CAMF）で送る2024-04-01

内閣府は、電源のある屋外の機器（街灯・サイネージ）や車載機器での利用を想定し、通信網が弱い山間部や地上の通信網が被災したときに役立つとしている。

どんな情報が配信されているか

MT43（気象庁の防災気象情報）

災害の種類は 12 種類。種類ごとに、配信を始める条件と配信を続ける時間が決まっている。

訓練・試験訓練用・試験用の通報

MT44（DCX）

  • J アラート：消防庁・関係省庁からの国民保護情報。今使われているのはミサイル関連の定型文で、ミサイル以外（ゲリラ・大規模テロなど）の枠は「予約」
  • L アラート：マルチメディア振興センター（FMMC）経由の避難情報
  • 自治体からの直接配信

避難行動の文は決まった文例から選んで送る。J アラートの文（ミサイル発射、通過、海に落下、日本に飛来しない、直ちに避難、迎撃により破壊 など）、共通の文（「直ちに命を守るための最善の行動を。」）、向き（とどまる・向かう・離れる）と場所（堅牢な建物、3 階以上、地下、山、水域、化学工場、崖）の組み合わせ。重大度は 4 段階（不明・中・重大・極めて重大）。

L アラートの「高齢者等避難・避難指示・緊急安全確保」のどれを配信するかの決まりは見つからなかった 未確認。アジア太平洋地域向けは 2025 年度開始の予定とされていたが、始まったかは確認できていない 未確認。

1 通に入る情報

1 通は 250 ビットで、中身に使えるのは 212 ビット。文章は送らず、すべてコードで送る。日本語の文にするのは受信機の側（qzss_dcr なら azarashi）。

  • 発表時刻は月・日・時・分まで（秒はない）
  • 1 通に入る地域の数：緊急地震速報は予報区を 80 ビットの表で送るので何区でも 1 通、震度 16 件、海上 8 件、気象 6 件、津波・火山・北西太平洋津波 5 件。超える分は複数通に分ける
  • MT44 の地域は、楕円（中心・軸の長さ・向き）、市区町村コード、都道府県コードの一覧のどれか

実際にどれくらい届くか

  • 年間や 1 日あたりの配信件数の統計は見つからなかった 未確認
  • 実例：2019-02-21 21:22 の緊急地震速報は、21:22:58〜21:24:34 に 24 回配信された
  • 平常時でも海上警報（着氷・風など）が届いた受信例がある。DCX は平常時は空で、配信はまれ
  • 内閣府の X アカウント @DisasterRept_QZ が配信のたびに投稿している。土砂災害警戒情報や記録的短時間大雨情報が多い
  • 海上警報はほぼいつもどこかで出ているので、MT43 が空になる時間は短いと思われる 推測

届くまでの時間

気象庁の発表から衛星で届くまでの公式な数値は見つからなかった 未確認。上の実例では発表 21:22（分単位）に対して配信開始 21:22:58 で、1 分未満としか言えない 推測。

最優先の情報が流れると訓練は中断し、中断した分は後から送らない。全国一斉の J アラート訓練も訓練の印を付けて流れる。MAX-M10S が届いたら、この日時に合わせて受信を確かめる。

法的な位置づけ

災危通報そのもの

  • 防災白書（令和 8 年版）に、内閣府が「準天頂衛星システムによる、災害関連情報の伝送を行う災害・危機管理通報サービス」を提供したとある
  • 利用条件：誰でも無償で使える。内容と提供は保証されない。人の生命・身体・財産に関わる用途では、冗長化・バックアップ・フェイルセーフなどの事故防止策を必ず取る。予告なく停止・変更することがある。内閣府と準天頂システムサービス株式会社は損害に責任を負わない
  • 根拠になる法律の条文と、防災基本計画での扱いは確認できなかった 未確認
  • 保証がなくフェイルセーフを求めている以上、公式の警報の伝達手段ではなく補完的なものと扱うのが妥当 推測

気象業務法

条文内容このプロジェクトでは
第 23 条 警報の制限気象庁以外の者は警報をしてはならない。一般的な警戒の呼び掛けは当たらないが、時と場所を具体的に示すと独自の警報とみなされるおそれがある独自の警戒の呼び掛けは出さない
第 17 条 予報業務の許可気象庁以外が予報業務をするには許可がいる。気象庁の予報を解説するだけなら不要。地震動は「気象庁や許可事業者が発表した予報をそのまま表示するなど許可が不要な場合があります」。受信端末で任意地点の震度や揺れが来るまでの時間を予想するには許可がいるそのまま表示するだけなので許可・届出は不要 推測。「ここの予想震度」「揺れまであと◯秒」は計算しない

気象庁の情報の利用規約

  • 気象庁 HP のコンテンツは「公共データ利用規約（第 1.0 版）」に従う。出典を書く（例：「出典：気象庁ホームページ（URL）」）。加工した場合はそう書く。国が作ったかのような見せ方をしない
  • XML の第三者提供や二次利用は、気象業務法の趣旨に反しない限り原則として制限がなく、商用でもよい
  • 公開 XML を使った行為について、気象庁は責任を負わない

J アラート・L アラート

  • J アラートは消防庁が自治体へ送り、防災行政無線などを自動で起動する仕組み。L アラートは FMMC が運営し、利用には申し込みがいる
  • 個人が本体を直接受ける経路はない。DCX 経由なら内閣府の無償・誰でも使える条件で受けられる 推測
  • DCX 経由で受けて表示することを制限する決まりは見つからなかった

モニターに書くこと

  1. 「みちびき災危通報（内閣府）と気象庁防災情報 XML を受信して表示しています。内容は保証されず、受信できない・遅れることがあります」
  2. 「公式の警報の伝達手段ではありません。テレビ・ラジオ・緊急速報メール・自治体の防災無線を優先してください」
  3. 出典。要約・加工したものはそう書く
  4. 発表時刻と受信時刻、受信経路（衛星かネットか）を分けて示す
  5. 独自の予想震度・揺れまでの秒数・独自の警戒の呼び掛けは出さない
  6. 訓練・試験の通報は「訓練」とはっきり表示する

QZS-1R186準天頂軌道送る

L1Sb は SBAS（航空用の補強）向けの別の信号。L1S の PRN は 183〜191 の範囲で割り当てる決まりで、qzss_dcr の作者は実機で PRN 184 と 189 から受信している。

静止軌道の QZS-3 は赤道の上空にいるので、日本からは常に南の空に見える。準天頂軌道の 3 機は日本の真上付近を交代で通る。アンテナは南向きの窓際に置く。

MAX-M10S から qzss_dcr まで

  1. --configure-m10 --ubx-port I2C が設定を 1 回送る。QZSS の L1S を受ける設定（CFG-SIGNAL-QZSS_L1S_ENA など）と、受けたメッセージを I2C に出す設定（CFG-MSGOUT-UBX_RXM_SFRBX_I2C）
  2. MAX-M10S は受けたメッセージを UBX-RXM-SFRBX で I2C に出す。qzss_dcr は先頭バイトが 5（QZSS）、3 バイト目が 1 のものを使う。3 バイト目は L1S を指すと推定 推測
  3. データ部の先頭 8 ワードを、ワードごとにバイト順を反転してつなぎ、250 ビットに切り詰める
  4. CRC-24Q で検査し、MT43・MT44 だけを azarashi で日本語にする。同じ通報は 300 秒の間、重ねて表示しない

これから作る I2C と TCP の中継プログラムは、バイト列を加工せずに両方向へ流せばよい。L1S が届いているかは qzss_dcr の受信状況表示（最後の L1S から 10 秒で黄、60 秒で赤）で確かめる。

--configure-m10 の設定は RAM にだけ書かれ、電源を切ると消える。起動のたびに付けるか、--persist で BBR（バックアップ用のメモリ）にも書く。systemd で常時起動にするとき（#11）に決める。

このプロジェクトでやること・確かめていないこと

やること

  • 中継プログラムはバイト列をそのまま流す
  • 起動時に毎回 --configure-m10 を付けるか、--persist を使う
  • 訓練の日に受信を確かめる。最初は 2026-11-26（MT43）と 12-01（MT44）
  • 画面に「モニターに書くこと」を表示する
  • 独自の予想震度や揺れまでの秒数は計算しない
  • 緊急地震速報・J アラートは衛星から、普通の警報・注意報は XML から取り、画面で合わせて出す

確かめていないこと

  • 年間・1 日あたりの配信件数
  • 気象庁の発表から衛星で届くまでの時間
  • 災危通報の根拠になる法律、防災基本計画での扱い
  • 公開 XML に緊急地震速報が入っていないこと（長期フィードを見た範囲になかっただけ）
  • L アラートのどの種類が DCX で配信されるか
  • アジア太平洋向けの DCX が始まったか
  • SFRBX の 3 バイト目の意味（実機で確かめる）

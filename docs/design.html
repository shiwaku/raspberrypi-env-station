raspberrypi-env-station 設計図

室内に置いた Raspberry Pi 4 で CO2・温度・湿度を記録し、気象庁の防災情報 XML とみちびきの災危通報を受け取る。結果は、帰宅に使う在来線と出張で使う新幹線の運行状況、よく使う便の遅延・欠航とあわせて、室内の大型モニターに地図とグラフで常時表示する。

災危通報を受信するしくみ

衛星 → アンテナ → 受信モジュール → Pi

MAX-M10S モジュールは、衛星の電波を数字のデータに変える部品。電波を拾うのは別売りのアンテナで、モジュールが解読した結果をジャンパーワイヤー 4 本で Pi に送る。Pi から見ると、シリアルポート /dev/serial0 にデータが流れてくるだけになる。

CO2 センサー（SCD40）は別の GPIO ピンにつなぐので、この流れとは独立して動く。

モニターの画面構成

60 インチ以上・1920×1080・3〜5m から読む

値・路線名・便は表示例。時間帯で配置を変えることも検討する（夕方〜夜は鉄道を大きく、日中はナウキャストと CO2 を主に）。鉄道と飛行機はデータの入手先を調査中（#12・#13）。

システム構成

入力 → Pi 上のプログラム → 出力

実線は実装済み・入手済み、破線は未実装・未購入。設置場所は動かないので GPS では測らない。

災危通報と気象庁 XML は役割が違う

気象庁 XML はインターネット経由で、警報・注意報や地震情報を詳しく得られる。災危通報は衛星から直接届くので、回線や停電でインターネットが止まっても受けられる。普段は XML、非常時の予備に衛星、という組み合わせになる。

高解像度降水ナウキャストの地図タイルは、Pi の画面に映した Chromium が気象庁から直接読む。ただしこのタイルは気象庁サイトの「雨雲の動き」用で、公開 API としての仕様は示されていない。利用規約と出典表示を確かめてから使う。

気象庁は「一度取得したファイルを再取得しない」実装を求めている（1 日 10GB を超えると IP 遮断）。取得済みの電文 ID を SQLite に記録して二重取得しない。

配線

GPIO 40 ピンのうち 1〜18 番を使う

TX と RX は交差させる（モジュールの TX → Pi の RXD）。※ スイッチサイエンス製モジュールのピン名と電源電圧は商品ページで確認できていないので、届いたら基板の表示と資料で確かめる。SCD40 の線の色は付属コードからの推定。

計測（実装済み）

env-station

設定ファイルを読み、決まった間隔で SCD40 を読んで SQLite に書く。--fake で実機なしでも動く。

設置場所（実装済み）

config.toml [station]

緯度経度を設定に書き、起動時に station テーブルへ記録する。地図に載せるときに使う。

災危通報（既存ツール）

qzss_dcr

MAX-M10S に L1S を有効にする設定を送り、受信した通報を日本語で表示・記録する。

気象庁 XML（未実装）

jma-feed

extra.xml（警報・注意報）と eqvol.xml（地震・火山）を毎分確かめ、新しい電文だけ取得して設置場所の地域で絞る。

鉄道・飛行機（調査中）

transit-feed

帰宅に使う在来線と出張で使う新幹線の運行状況（平常・遅延・運転見合わせ）と、最寄り空港からよく使う行き先への出発便の遅延・欠航を取る。データの入手先と利用条件を調べてから作る（#12・#13）。

Web ダッシュボード（未実装）

MapLibre GL JS・TypeScript

Pi 上の小さな Web サーバーが 127.0.0.1 だけで配信し、起動時に Chromium の全画面表示で 60 インチ以上の大型モニターに映す（出力は 1920×1080、3〜5m 離れて読める文字の大きさ）。共用 Wi-Fi の他の入居者からは開けない。地図に設置場所と高解像度降水ナウキャストを重ね、横に CO2・温湿度のグラフと警報・災危通報の一覧を並べる。

進め方

上から順に
  1. コワーキングの運営者に、共用 Wi-Fi につなぐ条件（端末の登録、認証方式、ブラウザでのログイン画面の有無、常時接続機器を置いてよいか）を確認する（#2）。電源・ケーブル・キーボードなど周辺機材の有無も確かめる（#3）。
  2. デスクトップ付きの Raspberry Pi OS を書き込み、大型モニター・キーボード・マウスをつないで起動する（SSH は無効のまま）。SCD40 を配線して i2cdetect -y 1 に 62 が出るか確かめ、env-station で計測を始める（#4）。
  3. MAX-M10S モジュールとアンテナを買い（#5）、UART で配線して qzss_dcr で受信を確かめる（#6）。
  4. ナウキャストの地図タイルの利用条件を確かめる（#7）。気象庁 XML の取得（jma-feed）を作り、設置場所の地域コードで警報・注意報を絞る（#8）。
  5. 鉄道（帰宅に使う在来線、出張で使う新幹線）と飛行機（よく使う行き先の出発便）のデータの入手先を調べる（#12・#13）。
  6. Web ダッシュボードを作り（#9）、起動時に大型モニターへ全画面で映るようにする（#10）。
  7. env-station・jma-feed・transit-feed・qzss_dcr を systemd で起動時に自動で動くようにする（#11）。

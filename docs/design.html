raspberrypi-env-station 設計図

室内に置いた Raspberry Pi 4 で CO2・温度・湿度を記録し、気象庁の防災情報 XML とみちびきの災危通報を受け取る。結果は、帰宅に使う在来線と出張で使う新幹線の運行状況、よく使う便の遅延・欠航とあわせて、室内の大型モニターに地図とグラフで常時表示する。

機材の全体図

衛星 → アンテナ → 受信モジュール → Pi ← CO2 センサー

MAX-M10S モジュールは、衛星の電波を数字のデータに変える部品。電波を拾うのは別売りのアンテナで、モジュールが解読した結果を Qwiic ケーブル（I2C）で Pi に送る。はんだ付けはしない。Pi では小さな中継プログラムが I2C（アドレス 0x42）から読んだデータを localhost:2101 の TCP に流し、qzss_dcr はそれを TCP 入力として受け取る。CO2 センサー（AE-SCD40-BO）は MAX-M10S の先に Qwiic でつなぎ、同じ I2C の線を通して env-station が直接読む。

CO2 センサー（SCD40）は MAX-M10S の先に Qwiic ケーブル（100mm）でつなぎ、同じ I2C の線を使う。アドレスが違う（MAX-M10S は 0x42、SCD40 は 0x62）ので、データは混ざらない。SCD40 は env-station が直接読み、MAX-M10S は中継プログラムを通して qzss_dcr が読む。中継プログラムは未実装。

モニターの画面構成

60 インチ以上・1920×1080・3〜5m から読む

値・路線名・便は表示例。時間帯で配置を変えることも検討する（夕方〜夜は鉄道を大きく、日中はナウキャストと CO2 を主に）。鉄道と飛行機はデータの入手先を調査中（#12・#13）。

災危通報と気象庁 XML は役割が違う

気象庁 XML はインターネット経由で、警報・注意報や地震情報を詳しく得られる。災危通報は衛星から直接届くので、回線や停電でインターネットが止まっても受けられる。普段は XML、非常時の予備に衛星、という組み合わせになる。

背景地図は国土地理院の地理院タイルを使い、淡色地図（pale）・標準地図（std）・シームレス空中写真（seamlessphoto）の 3 種類を切り替えられるようにする（URL は https://cyberjapandata.gsi.go.jp/xyz/{種類}/{z}/{x}/{y}.png、空中写真だけ .jpg）。API キーは要らず、画像タイルなので Pi 4 でも描画が軽い。既定は淡色地図にする。色が薄いので雨雲を重ねても見やすい。空中写真では雨雲が見えにくくなるので、雨雲の色や濃さを変えて重ねる。画面はマウスで操作しない前提なので、切り替えは設定ファイルで選ぶか、時間ごとに自動で替える。地図の隅に「地理院タイル」の出典を表示する。Pi には地図データを置かず、Chromium が Wi-Fi 経由で国土地理院のサーバーから直接読む。

高解像度降水ナウキャストの地図タイルも、Pi の画面に映した Chromium が気象庁から直接読む。ただしこのタイルは気象庁サイトの「雨雲の動き」用で、公開 API としての仕様は示されていない。利用規約と出典表示を確かめてから使う。

気象庁は「一度取得したファイルを再取得しない」実装を求めている（1 日 10GB を超えると IP 遮断）。取得済みの電文 ID を SQLite に記録して二重取得しない。

配線

GPIO は 1・3・5・6 番だけ使う · はんだ付けなし · 図は基板を上から見た向き

はんだ付けをしないため、MAX-M10S は UART ではなく Qwiic（I2C）でつなぐ。今 SCD40 に差している付属ケーブル（150mm）を MAX-M10S の Qwiic コネクタに差し替え、もう一つの Qwiic コネクタから Qwiic-Qwiic ケーブル（100mm）で SCD40 の CN1 へつなぐ。アンテナのケーブルは 3m なので、窓際から Pi まで 3m 以内に置く。付属ケーブルの Pi 側はメスのソケットなので、そのまま GPIO ピンに差せる。電源は 3.3V（1 番）で、MAX-M10S は Qwiic の 3.3V で動く（SparkFun 18037 の資料による）。線の色は Qwiic の標準（黒 GND・赤 3.3V・青 SDA・黄 SCL）。配線を抜き差しするときは Pi の電源を切る。

ソフトウェア構成

uv · Python 3.15 · Ruff · pytest

計測（実装済み）

env-station

設定ファイルを読み、決まった間隔で SCD40 を読んで SQLite に書く。--fake で実機なしでも動く。

設置場所（実装済み）

config.toml [station]

緯度経度を設定に書き、起動時に station テーブルへ記録する。地図に載せるときに使う。

災危通報（既存ツール）

qzss_dcr

MAX-M10S に L1S を有効にする設定を送り、受信した通報を日本語で表示・記録する。

気象庁 XML（未実装）

jma-feed

extra.xml（警報・注意報）と eqvol.xml（地震・火山）を毎分確かめ、新しい電文だけ取得して設置場所の地域で絞る。

鉄道・飛行機（調査中）

transit-feed

帰宅に使う在来線と出張で使う新幹線の運行状況（平常・遅延・運転見合わせ）と、最寄り空港からよく使う行き先への出発便の遅延・欠航を取る。データの入手先と利用条件を調べてから作る（#12・#13）。

Web ダッシュボード（地図・CO2 まで実装）

env-dashboard · SvelteKit・MapLibre GL JS・TypeScript

Pi 上の小さな Web サーバーが 127.0.0.1 だけで配信し、起動時に Chromium の全画面表示で 60 インチ以上の大型モニターに映す（出力は 1920×1080、3〜5m 離れて読める文字の大きさ）。共用 Wi-Fi の他の入居者からは開けない。背景地図の地理院タイル（淡色地図・標準地図・シームレス空中写真を切り替え）に設置場所と高解像度降水ナウキャストを重ね、横に CO2・温湿度のグラフと警報・災危通報の一覧を並べる。

進め方

上から順に
  1. コワーキングの運営者に、共用 Wi-Fi につなぐ条件（端末の登録、認証方式、ブラウザでのログイン画面の有無、常時接続機器を置いてよいか）を確認する（#2）。電源・ケーブル・キーボードなど周辺機材の有無も確かめる（#3）。
  2. デスクトップ付きの Raspberry Pi OS を書き込み、大型モニター・キーボード・マウスをつないで起動する。SSH は鍵の認証だけを許し、以降は PC の Tera Term から作業する。SCD40 を配線して i2cdetect -y 1 に 62 が出るか確かめ、env-station で計測を始める（#4）。
  3. MAX-M10S モジュールとアンテナを買い（#5）、Qwiic（I2C）で配線する。I2C と TCP の中継プログラムを作り、qzss_dcr で受信を確かめる（#6）。
  4. ナウキャストの地図タイルの利用条件を確かめる（#7）。気象庁 XML の取得（jma-feed）を作り、設置場所の地域コードで警報・注意報を絞る（#8）。
  5. 鉄道（帰宅に使う在来線、出張で使う新幹線）と飛行機（よく使う行き先の出発便）のデータの入手先を調べる（#12・#13）。
  6. Web ダッシュボードを作り（#9）、起動時に大型モニターへ全画面で映るようにする（#10）。
  7. env-station・jma-feed・transit-feed・qzss_dcr を systemd で起動時に自動で動くようにする（#11）。
